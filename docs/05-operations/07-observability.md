# Observability implementation and bindings

`infrastructure/observability/alerts.yaml` and `service-dashboard.json` are portable definitions. They are **unbound**, do not contact a monitoring provider, and have not been exercised against a deployed alert receiver. Choosing the monitoring product, deployment resources, routing, staff roster, access controls and retention remains deployment work. No compose or monitoring service is added by these files.

The source distinguishes existing sanitized log events (`available: true`) from required projections (`available: false`). A required projection is a binding contract, not an installed metric. The importer must refuse activation of any rule whose source is unavailable; an empty source must never look healthy. Financial projections must run under a reviewed role and emit counts or reconciliation codes only. Amounts and addresses do not belong in the generic log pipeline. Correlation uses `requestId`, `correlationId`, `causationId`, `runId` and `workflowId` where the emitting path supplies them; absence is not fabricated.

Existing event sources include dispatcher delivery problems, tombstone ledger backlog, restore gate closure and operator erasure results. A dispatcher backlog event has `count` and `oldestSeconds`; the standalone ledger diagnostic uses `queued` and `dead`, so an importer may explicitly derive `count = queued + dead` for that diagnostic. `dispatcher.delivery_problem` emits only an aggregate `count`, combining failed, dead and deferred deliveries; it does not expose a separate dead count. That projection is therefore marked unavailable. An importer must not silently assume omitted fields are zero. Queue latency, authenticated web latency, cost review, unsettled-payment counts and security signal aggregation still require actual instrumentation/adapters. In particular, no exporter currently proves every cross-tenant incident or compromised credential will produce a signal.

Every numeric alert boundary is a **tuning value**, subject to measurements and operator review. It is not an SLA, response deadline or error budget. P0 routing covers cross-tenant policy signals, forbidden egress, compromised keys and repeated verified duplicate effects. M8 rules cover unknown payments, unmatched events, overdue invoices lacking a policy, failed erasure, restore pending and dead outbox events. Each rule points to an existing runbook anchor.

The dashboard carries operational counts and durations. Cost per accepted outcome must join the actual M4 ledger to verified outcomes under authorized access and disclose its currency basis. A projection cannot convert credits into money or infer a missing exchange rate. BYOM inference must remain informational and outside Ensemus prepaid model charges. The cost panel is marked unavailable until that binding exists.

Default telemetry is the `SAFE_FIELDS` allowlist in `packages/telemetry/src/index.ts`. Do not add a provider response, email, ticket body, bill-to, amount, prompt or incident private reference to a label or log line. Public status reads explicit columns under application-role RLS, not the operator connection. The 0506 projection migration further removes staff and author columns from application-role grants; it requires migration review and actual-role tests before release.
