# Delegated inputs: trusted attempt receipts (0416, first source checkpoint)

This checkpoint implements the pre-network main-attempt receipt only. It does **not** reopen delegated child creation, child Work/file serving, legacy child migration, source-erasure completion or tenant erasure. All 0414 unproven-child gates remain in force. No child observations or legacy receipts are backfilled.

The real gateway takes a private copy of its compiled request before asynchronous work. A separate SHA-256 binds the exact provider-neutral SDK prompt rendering, role fences, function wire names/descriptions/schema, trusted tool versions, response format, model/endpoint/provider options, output bound and timeout. Existing message-only audit hashes, input-byte/token calculation, prices, usage keys, reservation/recovery accounting and fallback policy keep their existing meanings.

Before money moves, the actual main-admission transaction rechecks the immutable manifest lineage, actual named initiator, current and historical company inputs, current profile/policy, counters and full main envelope. It then writes one `ai.main_input_snapshots` row for the actual run/step/model attempt/reservation attempt. The bounded metadata inventory preserves actual observation hashes, flattened artifact/record dependencies, Knowledge package/item/fact hashes, actual auxiliary call/input identities, and current parent/source/document authority metadata. Authority-only parent refs have no invented body hash. Multiple actual historical hashes survive. Current mutable body hashes are not used as a visibility equality test.

A unique attempt key and separate per-invocation writer token prevent a duplicate invocation from borrowing another invocation's hold and later releasing it. Immediately before the adapter call, dispatch atomically claims prepared → dispatched once and refuses a changed input prefix. Later parent reads remain in the parent's ledger; they do not alter an earlier dispatched snapshot. No wall-clock cutoff, ID ordering or empty-history guess is used as commit-order proof.

After output validation and canonical usage settlement, the gateway records only the known response kind, trusted tool ID and exact serialized tool-argument/final-text hash. Unknown, rejected, stale, fenced or lost responses never gain this receipt. Receipt failure discards content after settlement; it does not release paid holds or retry the provider. `ai.model_proposal_inputs` binds the stored proposal's exact payload hash to that immutable original attempt. Model arguments do not choose a snapshot. Legacy/scripted proposals without this proof stay unqualified for future delegation.

`knowledge.evidence_package_facts` persists each included fact's exact already-computed in-memory compiler hash and captured class in the same transaction as its package/items. The compiler already requires every included fact's evidence to be selected; publication additionally compares the complete previously read evidence set against current immutable evidence IDs/hashes. Later additions or replacements refuse. Package publication takes checkpoint/run locks after body/source locks, serializing with main snapshots. Old fact packages without these receipts are explicitly unproven, even if a current fact lookup happens to return the same claim. Package/model-call overall protection can include internal policy text; a later company-data-ceiling join must use the individual company inputs, not promote that protection label into a fabricated company-data read.
