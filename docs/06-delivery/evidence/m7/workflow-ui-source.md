# Workflow authoring UI source

This is a source-only follow-up on `codex/m7-workflows`, based on root `148fd8a` plus the five Studio detail/review pages (`3a2a25f`, preserving original `98a61c1`). It does not claim runtime acceptance or milestone completion.

Actual routes are `/studio/workflows`, `/new`, `/[draftId]` and `/[draftId]/edit` beneath the organization. They use the existing native Studio gate, tenant-aware process draft DAL and current compiler/catalog. The editor uses ordinary labeled forms for definition name/sensitivity and point types, labels, assistants, outside-action tools, approval roles, evidence and explicit earlier/later connections. There is no JSON-only editor or pretend canvas. Graph coordinates remain unchanged on point edits; they are not presented as a graphical feature.

Connections support the domain's actual forks and joins: all selected prerequisites finish before a point proceeds; every outgoing path is followed. No conditional routing is invented. Adding a point replaces existing direct connections only when that explicit checkbox is selected. Removing a point deletes exactly that point and its incident connections without reconnecting other paths. A duplicated-ID group requires explicit group removal; the UI never chooses an arbitrary duplicate to edit. Saved dangling/self connections and unavailable selections remain visible for explicit correction. Partial graphs can be saved, with compiler issues shown in plain language; they acquire no passing hash by assertion.

Every mutation calls `createProcessDraft` or `updateProcessDraft` with the actual expected version, through the existing identity-only `studioOnce` helper. The input hash binds the explicit form intent. Reads used to assemble a point edit occur outside the effect transaction; the real kernel locks and checks the source version before applying it. Retries reread the actual authorized draft rather than replaying private content. Unknown faults propagate with fixed telemetry codes; native SSO/MFA refusals use the existing flow. No new default MFA rule, delegated-user cast, SQL authority bypass or replacement kernel is introduced.

Assistant choices intersect actual published catalog version identities with actual active M4 registry metadata, using real names. Unavailable catalog ports remain `null`, not fake empty success. Existing unavailable selections are preserved; no tool or assistant facts are invented. The registry metadata is currently bounded, so unconfirmed offered choices remain unavailable instead of receiving fabricated labels. Root was notified that a complete named/current catalog projection would improve this seam.

The standard `standard.process` rehearsal uses the real immutable simulation request/outbox. Review requests use `subjectKind: process_draft`, an actual passed current-hash report, and a current named eligible reader. The existing frozen review/decision/publication pages are reused. Editing or requesting review starts no workflow run, model call or outside action. Workflow start, run detail and catalog execution are separate later work.

Two actual availability constraints are kept explicit. `starter_manager` cannot be resolved because the runtime records no manager relation, so it is not offered as a new functioning approval route; an existing selection is preserved as unavailable. A restricted process draft is owner-only under the current access policy while elevated publication needs an independent reader. The UI and its action filter actual reviewers with `canProduct` and `canReadRecord`, refuse knowingly unreviewable requests and explain the missing approved access path. No classification downgrade or access grant is manufactured. Root owns any future explicit named-review access solution.

The existing five-page follow-up changes only real workflow return links after these paths exist and corrects frozen approval-role copy to the actual runtime resolver: workflow publisher or an eligible administrator, not an invented fixed manager/owner assignment. Root owns Studio hub/navigation, global CSS, shared actions/DAL, SQL, journals and deployment wiring. No provider connection picker is invented: the graph selects a supported action type, while actual runtime connection/payload/action approval requirements stay with M3 and the real dispatcher.
