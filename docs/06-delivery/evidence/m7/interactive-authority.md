# Interactive authority source checkpoint

2026-11-07. ID-05, ADR-031 D8, TR-031. This is a separate source delta after the checked `c28e97e2` M7 join. It is not a migration execution, native-provider acceptance or a security review.

The native Better Auth `getSession` verifier now supplies a frozen, process-local registered identity. The database package exposes its type and resolver; its constructor is available only through the auth-only entry point. JSON, a copied object or a DTO session UUID cannot construct the handoff. The ordinary server tenant/API boundaries derive it from actual cookies, preserve the existing restore and SSO gates, and still use the lazy runtime and object store. Every transaction clears the interactive-session binding unless an actual user context retains that issued identity. Agent, delegated, service and different-user context copies lose it.

This process-local provenance and the SQL binding are different trust boundaries. PostgreSQL custom settings are not unforgeable credentials. An arbitrary caller already holding the application database credential can set them. The SQL guard independently validates the bound account and exact own live session against an auth-only second-factor receipt, enabled-factor state, current membership and policy. It does not claim to cryptographically prove which browser supplied a transaction setting. The application role cannot write a receipt, read a session token or read a factor secret through the new seam.

The effect transaction uses `assertInteractivePrivilege(tx, context, action)` or the existing `assertRecentMfa` signature. A caller-supplied Date cannot control SQL expiry. `withPrivilegeTx` maps the fixed `EN405` trigger refusal to `MFA_REQUIRED`, including a second refusal after waiting for the target lock. Fixed audited codes and the actual existing step-up route handle the HTTP/form denial; no credential or request text enters an audit reason.

## SQL and effect mapping

`0404_interactive_privileges.sql` is additive source and remains unjournaled/unapplied. It uses the already owning migrator role for one fixed metadata-only guard with `search_path=pg_catalog` and qualified references. The migration refuses an unexpected owner, a superuser/BYPASSRLS owner or a migrator that belongs to the auth role; a regression inspects that actual ownership. There is no `ALTER OWNER`, auth-role membership, `SET ROLE` grant, factor/account secret read, or application session mutation grant. Exact self/session forced-RLS policies provide lock-only session/assurance visibility with `WITH CHECK(false)`. Existing 0401 operator user/assurance metadata policies are reused. Private internal scope is restored on success and error. Session, user and assurance locks cover effect completion; the database clock is evaluated after waiting.

The literal action tiers preserve the opt-in-off administration default. M4 agent publication and model probe requests always require recent MFA. Member, team and connection management require it only after `mfa_for_administration` is enabled. Security policy changes remain owner-only and always require it. The explicitly approved new `model_workload.approve` action is always privileged; model qualification uses `model_profile.activate`, and conservative workload revocation has no added MFA obstacle.

SQL backstops cover actual M4 agent-version/publication insertion/change, model pending/activation transitions, security/SSO/token management, M2 member/team/organization management, invitations, connections and webhook configuration. A final SQL-only addition also guards INSERT of 0216's immutable `ai.model_workload_approvals`, using `model_workload.approve` and the actual approving membership. Its separate bounds/capability trigger remains required, and one-way revocation has no new MFA check. **0216 is an explicit prerequisite of 0404**; there is no optional-table fallback. The serving DAL effects call the same helper before their target mutation. Existing M7 product calls continue to use the shared recent-MFA helper; this delta does not claim that every unfinished M7 foundation already has a complete SQL effect backstop or vertical slice.

Explicit durable compatibility paths remain narrow: same-transaction first-owner bootstrap; a real live invitation's exact recipient acceptance or current manager confirmation; verified, opted-in member-only SAML auto-join; live token/provider/link SCIM status transitions and the prior human re-disable receipt invalidation; unused invitation cleanup after the inviter loses access; fixed connector/webhook bookkeeping and revocation settlement. Invitation recipient verification needs only the added `SELECT(email_verified)` account-status metadata grant under existing self/tenant RLS. No generic service/agent exception grants a privileged effect.

An accepted invitation cannot be touched again. Server-assigned tuple transaction identity binds the membership insert to that transaction's actual invitation consumption, rather than permitting replay of a previously accepted row. Current invitation/bootstrap DAL paths use their own top-level transactions. A future nested-savepoint caller must revisit this fail-closed transaction-identity admission; no permissive fallback is implemented.

## Durable model probe admission

Four nullable fields on `ai.model_profiles` bind the pending request to its exact version, real requesting membership, session ID and server time. The session ID has no live-session FK: logout or expiry does not revoke an already authorized bounded probe. A configuration/version change or disable clears pending admission. Unknown legacy pending requests remain refused until the actual existing “Ask for the test again” action reauthorizes them.

The application and agent cannot update those fields. The existing table-level INSERT grant must remain for ORM `DEFAULT` values, so an insert trigger refuses any caller-supplied non-null receipt. Only the actual guarded transition stamps it. This receipt admits a test; it does not assert a passing model qualification, enable an unproved capability, authorize company-data egress, or replace M8's separately required qualification proof. The real worker profile loader checks the same exact-version receipt before any probe work.

M8's `requestModelQualification` must bind its `ModelAuthorityAdmission.assertInTx` port to `assertInteractivePrivilege(..., 'model_profile.activate')`, and `approveModelWorkload` must bind it to the same helper with `model_workload.approve` inside its effect transaction at the later join. Its independent qualification/egress/budget proof guards must remain. Root's additive `pinAgentVersion` must use `agent.publish` and the normalized transaction boundary; publication INSERT/UPDATE is already included here. The M8 organization erasure/suspension lifecycle requires its own explicit persisted-intent compatibility path at composition; this older checkout has no such authority to infer and adds no blanket service exemption.
