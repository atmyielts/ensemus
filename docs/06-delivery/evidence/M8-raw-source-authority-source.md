The storage foundation adds an actual single-attempt PUT transport separate from existing general PUT. Native success requires the modeled200/ETag response; an error or unexpected response is unknown. Body bytes are captured and Content-MD5 is supplied. [The official S3 PutObject contract](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html) describes whole-object success; compatibility and actual backend behavior remain qualification gates. The existing general PUT and all legacy/derived/archive writer receipts retain their old contract. No previous settled state is upgraded to this protocol.

Two private retained metadata models are authored: source/organization native birth and purge inventory, and document catalogue/all exact writer generations. They deliberately have no live source/document/writer FK that could cascade history away. The generation-zero catalogue row will be an actual future document INSERT witness, not a made-up past writer or an absence certificate. Future positive cleanup still requires complete native inventory and actual admitted DELETE/physical proof. Existing tenant/source history and restore generations remain independent unqualified debt.

This is a recoverable foundation checkpoint, not source completion or lifecycle acceptance. Still being authored:0516 SQL inventory/claim/hold/completion guards; private native result brand and guarded settlement; actual runtime bindings; four cleanup paths; completion/status fast-path requalification; positive/denied/unknown/restore source tests.
