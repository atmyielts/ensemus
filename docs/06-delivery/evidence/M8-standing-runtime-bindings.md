## 0511 authority

Unregistered `0511_standing_agent_stops.sql` adds only the private metadata table `lifecycle.standing_stop_receipts`. A fixed `billing.standing_changes AFTER INSERT` trigger records actual INSERT birth and the server transaction identity. A separate actual `org.organizations AFTER UPDATE OF lifecycle` trigger applies only one matching same-transaction birth to the exact OLD→NEW transition. Timestamp or xmin equality is never used as INSERT provenance. The caller cannot insert or update a receipt.

The fixed service RPC may create a new organization stop or release owned stops only from that actual current transition witness. A settled exact receipt can replay without new effects. A deferred constraint checks that every ordinary active/read-only/suspended transition has settled its required stop effect before commit. A no-op injected port therefore cannot commit a positive standing change. Offboarding, cancellation and erasure keep their existing0508 admission and separately owned switches; normal standing release never adopts them.

Stop release joins receipt-owned switch IDs. Another stop with the same reason code is still independent. Generic human release and an actual agent login using `SET ROLE ensemus_app` cannot release these owned stops. No app/agent table SELECT or mutation grant is added; fixed migrator metadata functions use forced RLS and restore `lifecycle.standing_org` on success and error. The generated deferred constraint pins its actual NEW receipt organization even if an outer savepoint restored ordinary bindings. Custom GUCs are scopes, not unforgeable credentials; the authority is the actual roles, immutable INSERT/application witnesses and exact fixed SQL operations.

Root must add `lifecycle.standing_org` to the generic/default/nested transaction clear inventory at composition. The schema model and unpublished `/3` portability inventory name the new table as operationally excluded; `/1` and `/2` are unchanged. The metadata is retained under the existing lifecycle retention rule. No0511 journal/snapshot or0999 installation is performed here. Actual deferred constraints, lock visibility, role grants, savepoint restoration and concurrency still need PostgreSQL qualification.

## Disabled financial execution

Billing, credit and tax Activities now require actual server `billingEnabled === true` before any database/new invoice/credit/tax transport effect. Missing means disabled, including queued or replayed workflow work. Main/connector composition passes the real deployment flag; it does not infer enablement from a subscription or successful reader. Positive integration fixtures call the actual standing port, with spies around it where counts matter. Explicit refusal/orchestration doubles stay local to those tests.

Payment connector recovery is an open follow-up, not acceptance: existing attempts do not pin the original billing connection/configuration/credential identity. Using a replacement connection to certify absence could permit an unsafe resend. Root approved a separate0512 binding design. New charging must not be enabled merely by this usage join, and missing/changed/legacy binding must stay unconfirmed without erasing UNKNOWN debt. No processor or gateway adapter is configured by this source.

Cloud prepaid admission is also OPEN and unaccepted. The compatibility checker currently asks model capacity with an estimate of zero. A positive balance and later ledger consumption do not prove atomic prepaid limits across concurrent calls, and KnowledgeCloudSpend has no actual M8 implementation. Cloud must remain unavailable until actual approved credit-card/ceiling holds bind to dispatch and settle exactly once without an invented USD/credit conversion or a second debit of `usage:<id>`. The following checkpoint is a source join, not permission to enable Cloud inference.

After the checked0511 checkpoint, the bound commercial runtime explicitly refuses Cloud even when that compatibility result is positive. This is a code-level refusal, with no configuration Boolean that can waive missing holds. New runtime unit and revised integration sources document the refusal and preserve BYOM/Sovereign behavior; these later edits are UNRUN until another source slot. Actual prepaid dispatch/settlement remains implementation work, not an accepted disabled feature.
