Date: 2026-11-07. Branch: `codex/m6-integration`, starting at `38344e4`.

This is a source checkpoint for `COMM-05`, `OPS-02`, `SEC-05` and the portability/restore portions of `SOV-01`–`SOV-06`. It does not accept M6, a production migration, provider behavior, an offline bundle or an independently operated restore. The license corpus, license verification and maintenance behavior are unchanged.

## Implemented source

- Archive v2 declares the exact `ensemus.m3-m5/1` table inventory, reviewed dispositions and exact per-section record/part totals. Missing, duplicate, unknown or unimplemented sections fail closed. The worker registry now includes real `agents`, `policy` and `knowledge` adapters as well as the eleven core sections. `skills` is explicitly empty because the actual M4 manifest permits no skills; this profile has no Studio custom-object tables.
- Reviewed SQL projections cover M3 resource/ACL/MCP identity and action-attempt metadata, M4 identities/agent definitions/specs/profile settings/run counters/usage/budgets/policy definitions, and M5 sources/grants/document versions/fact claims/evidence/edges/citation metadata. Sealed-secret references, credential/config columns, profile endpoint URLs, opaque sync cursors, private step payloads/tool proposals, private question/answer/evidence-package content and generated search vectors are excluded. Free-form authorized business text remains business data; this is a column allowlist, not a claim to detect a credential manually pasted into text.
- Original knowledge files use bounded encrypted `knowledge/{document-id}.bin.sealed` parts. Export reads one original per page, at most 25 MiB, outside SQL transactions, checks its length/hash and rechecks current source authority before recording the page. Only explicitly ordinary artifacts use the ordinary-file path; generated/unknown outputs are omitted and counted rather than losing provenance by becoming ordinary uploads.
- Uploaded originals import under an active named custodian with a real source/document reservation and durable writer token before storage I/O. They return as unprocessed content; no model/provider is called. Exact immutable reservation content permits a retry through the empty-target check, while an active/unknown writer still refuses another put until an actual recovery adapter proves quiescence. A settled retry verifies the existing bytes. Historical version metadata is preserved without claiming old search or verification state.
- Authority-bearing definitions/history are quarantined, with a server-rendered, JavaScript-independent inspection page at `/o/{organizationId}/data/definitions`. They confer no agent publication, active policy, provider grant, approval, verified fact, accepted artifact or executable run. Uploaded source grants are review material; the target gets an explicit named custodian grant rather than automatically granting old organization/team permissions.
- Provider-backed source definitions require a new connection and current permission reconciliation. This import does not turn them into user uploads or persist their original bytes as a newly authorized live source. Their originals remain recoverable from the customer-held archive with the standalone tool.
- Quarantined records retain all their typed source and Work/client/project references. Inspection requires fresh source/record visibility, live state, no tombstone and a current class no stronger than the pin. Historical references do not require unchanged Work text hashes. Unknown provider sources remain unservable. Narrow service erasure/count functions and `createImportedDefinitionPurge` expose a positive PG-copy proof to lifecycle owners; normal application DELETE is not granted.
- Four required restore owners have real tenant-SQL audits: runs/budgets, private transcripts, source/index state and derived artifacts. Missing recovery bindings contribute attention; private payloads are never read through the application role. Required contributor names are checked before ledger I/O, including an empty restored tenant list. Report mode cannot qualify skipped contributors.
- Migration `0303` pins a monotonic tenant export epoch at the actual begin transition. Fixed triggers observe relevant grants, source/provider state/class, membership/team access, Work/client/project access, artifact links/class/citations and tombstones. Routine Work status/version progress does not advance it. Changed/missing pins close manifest creation and download; legacy exports are not auto-pinned. Readers use plain SELECTs and check before/after bounded I/O and at stream boundaries. No lock spans storage I/O. Previously delivered bytes cannot be recalled.
- The standalone customer tool reads both v1 and v2. V2 inventory and totals are validated before output publication, including original knowledge files. It uses bundled pure rules and Node; no database, deployment or provider is needed to decrypt an owned archive.
